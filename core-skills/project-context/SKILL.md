# Project Context

1. Inspect the actual project and authoritative artifacts before writing.
2. Use `templates/PROJECT_CONTEXT.md` when available.
3. Capture purpose, users, value, business model, architecture, core flows, constraints, scope, vocabulary, and active risks.
4. Distinguish confirmed facts, open questions, and hypotheses.
5. Keep the file concise; link detailed specifications and evidence.
6. Update the `Last verified` field and describe what was checked.
